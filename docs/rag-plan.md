Plan: Fix follow-up context for Local RAG (config/prompt-only)

Problem
- Follow-up user questions (e.g., "What is the condition?") are not resolved using previous turns; the RAG assistant returns a generic answer rather than using earlier chat context.

Goal
- Make follow-up questions resolve correctly by using conversation-aware prompting and retriever configuration only (no code+tests requested).

Proposed approach (config / prompt changes)
1) Rolling-history in the prompt: include the last 2–3 user/assistant turns (concise) in the system or retrieval prompt so retrieval and answer generation have immediate conversational context.
2) Short conversation summary: before retrieval, add a 1–2 sentence condensate of prior turns (generated by the model) and pass it to retriever as additional context to bias document scoring.
3) Question Rewriting (lightweight): add a prompt step that rewrites a follow-up into a standalone question using the included short history; use this rewritten query for retrieval when available.
4) Retriever config: enable conversation-aware ranking (pass conversation summary and/or recent turns as metadata to the retriever) and increase top_k for candidates slightly (e.g., +2) to avoid missing relevant snippets.
5) Chunking/windowing: tune chunk size and overlap to ensure clauses (like offer letter conditions) aren’t split across chunks; increase overlap modestly (e.g., 100–200 tokens) for safety.
6) Frontend payload: ensure the chat client sends a concise recent-history payload (last N turns or a flag to request server-side summary) with each user turn.
7) Prompt-level grounding: instruct the LLM to prefer cited document excerpts and to explicitly indicate when documents do not define a term.

Acceptance criteria
- A follow-up question referencing a previous answer resolves correctly to a specific clause in the indexed docs and the assistant cites the correct source.
- When docs lack explicit detail, the assistant states that clearly and avoids hallucination.

Todos
- update-prompt-template: Modify the retrieval+answering prompt templates to include rolling history, rewriting instructions, and grounding guidance.
- enable-conversation-aware-retriever: Configure retriever inputs so conversation summary or recent-turn metadata is used in scoring.
- adjust-chunking-window: Tune chunk size/overlap to keep clauses intact and improve passage relevance.
- validate-manually: Manually test follow-up flows with sample docs (offer letter examples) and confirm sources and behavior.

Notes
- This plan avoids code-level tests per request; if later desired, a small automated test harness (end-to-end QA) can be added.
- If the retriever library lacks metadata-aware ranking, the prompt-side question-rewrite + rolling-history will still provide major gains.
